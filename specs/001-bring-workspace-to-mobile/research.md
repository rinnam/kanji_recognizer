# Research decisions

| Decision | Rationale and evidence | Alternative considered |
| --- | --- | --- |
| Package the existing Vite output with Capacitor in the frontend package. | The workspace already handles responsive tabs, folder scope and themes. Keeping one build entry implements the constitution and avoids a repository-wide move. See [architecture](../../docs/architecture/cross-platform.md) and [Capacitor setup](https://capacitorjs.com/docs/getting-started). | A second native UI would duplicate behavior. A hosted URL would make first launch depend on connectivity. |
| Retain IndexedDB behind the existing web storage boundary and keep the native app identity and local origin stable across upgrades. | Existing browser data belongs to its origin. The owner selected browser-to-server sync followed by phone sync. Validate restart and in-place upgrade on both physical platforms before acceptance. | A second SQLite model introduces conversion and recovery obligations without an established need. |
| Use successful committed pull progress to identify the first completed sync. | SyncProvider currently sets a one-time cleanup flag before calling resetAndPullFromServer, which clears vocabulary. That path can discard offline work and its flag can survive a failed request. Normal runSync already pushes dirty rows in dependency order. | A first-boot seed, full replacement or connectivity flag cannot establish successful reconciliation. |
| Compare incoming rows with current local rows when committing a pull. | runSync takes a local snapshot before network requests. A user can edit during the request. Test the race and commit winners plus pull cursor atomically. | Reusing the pre-request snapshot permits an older incoming value to overwrite a confirmed edit. |
| Configure a reachable HTTPS API base for packaged builds. | The browser development proxy supplies /api; packaged assets have a device-local origin. Keep database credentials server-side and constrain access to the intended service and origins. | Bundling localhost or widening production transport exceptions would not provide a deployable phone endpoint. |
| Exercise browser file input and audio on both phones before introducing native plugins. | Preserve file/paste preview, cancellation and playback behavior through the existing feature entry points. If a platform needs a bridge, isolate it behind a typed capability. | Duplicating import or study rules in a plugin would produce divergent results. |

Dependency selection during implementation: pin mutually compatible Capacitor core, CLI and platform packages in the frontend lockfile. Verify their Android Studio/SDK and macOS/Xcode requirements on the build hosts before generating projects.

Generate the Android and iOS projects once with the local CLI. After each web build, sync the bundled assets into the native projects. Omit server.url from acceptance builds so the first offline launch reads local assets. See the [native workflow](https://capacitorjs.com/docs/basics/workflow) and [configuration reference](https://capacitorjs.com/docs/config).
